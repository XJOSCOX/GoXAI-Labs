# Cloudflare R2 setup

GoXAi Lab uses Supabase for auth/Postgres and Cloudflare R2 for large dataset files.

## Environment

Fill these values in `.env`:

```env
R2_ACCOUNT_ID=
R2_ACCESS_KEY_ID=
R2_SECRET_ACCESS_KEY=
R2_BUCKET=
R2_ENDPOINT=https://YOUR_ACCOUNT_ID.r2.cloudflarestorage.com
R2_PUBLIC_BASE_URL=
```

`R2_PUBLIC_BASE_URL` is optional for now. Use it later if the bucket has a public/custom domain for read access.

## Bucket CORS

Direct browser uploads require CORS on the R2 bucket. Multipart resumable uploads also require `ETag` in `ExposeHeaders`, because the browser must send completed part ETags back to the API before R2 can assemble the final object.

In Cloudflare:

1. Open **R2 Object Storage**.
2. Open your bucket.
3. Go to **Settings**.
4. Find **CORS policy**.
5. Add a policy like this for local development:

```json
[
  {
    "AllowedOrigins": ["http://localhost:5173"],
    "AllowedMethods": ["PUT", "GET", "HEAD"],
    "AllowedHeaders": ["Content-Type"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3000
  }
]
```

Add the production web origin before deploying, for example:

```json
"AllowedOrigins": ["http://localhost:5173", "https://your-domain.com"]
```

Cloudflare matches origins exactly. Do not add a trailing slash or path, so use `http://localhost:5173`, not `http://localhost:5173/`.

After saving the policy, wait about 30 seconds and run:

```bash
pnpm check:r2-cors
```

The output should show `"preflightStatus": 200` or `"preflightStatus": 204`, `"allowOrigin": "http://localhost:5173"`, and `"ok": true`.

## Current upload flow

1. For files under 64 MB, the frontend requests `POST /api/assets/upload-url`.
2. The backend validates dataset access and signs a short-lived R2 PUT URL.
3. The browser uploads the file directly to R2.
4. For files 64 MB and larger, the frontend starts `POST /api/assets/multipart/start`.
5. The browser uploads 16 MB parts directly to R2, stores completed part ETags in local storage, retries failed chunks, and can resume if the user selects the same file again.
6. The frontend calls `POST /api/assets/multipart/complete` so R2 assembles the final object.
7. The frontend registers the uploaded object through `POST /api/assets`.

Large files do not pass through the Express API.

Dataset upload folders are assigned by the web app instead of typed manually. Incoming dataset files live under `dataset/import/`. The first folder uses the dataset name plus a short code, for example `dataset/import/video-2026-2x5rth`. Later uploads reuse the same folder until it reaches 250 registered files, then continue into numbered folders such as `dataset/import/video-2026-2x5rth-1`. Outgoing dataset exports live under `dataset/export/`.
